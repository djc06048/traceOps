# TraceOps 단순 버전

상세공정관리(분석 / 설계 / 개발단계)와 테스트관리(단위 / 통합테스트)만 구현한 프로토타입입니다.
DB 없이 `data/*.json` 파일을 읽어서 동작합니다. 기준 화면은 `설계단계조회및관리_5.html`입니다.

## 실행

`fetch`로 JSON을 읽으므로 파일을 더블클릭하지 말고 로컬 서버로 실행합니다.

```bash
cd traceops-simple
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000` 을 엽니다. 화면 주소는 `#analysis`, `#design`, `#dev`, `#unit`, `#integration` 입니다.

## 폴더 구조

```
traceops-simple/
├─ index.html        화면 골격
├─ css/style.css     디자인 토큰과 공통 스타일
├─ js/app.js         공통 엔진 (목록, 필터, 편집, 검증, 팝업, 저장)
└─ data/             모든 데이터 (이 파일을 고치면 화면이 바뀜)
   ├─ master.json        담당자, 시스템/서브시스템, 요구사항ID, 물리ID, 처리유형 목록
   ├─ analysis.json      분석단계 항목
   ├─ design.json        설계단계 항목
   ├─ dev.json           개발단계 항목 (설계ID 참조)
   ├─ unit.json          단위테스트 케이스
   └─ integration.json   통합테스트 케이스
```

## 데이터 편집 방법

- **기본 데이터 변경**: `data/*.json` 을 직접 수정합니다. 항목 하나는 `items` 배열의 객체 하나입니다.
- **화면에서 편집**: 저장 시 이 브라우저(localStorage)에만 임시로 남습니다. 다른 사람과 공유되지 않습니다.
- **화면 편집 내용을 반영하려면**: 화면 상단 `내보내기`로 JSON을 받고, `data/` 의 같은 이름 파일에 덮어씁니다.
- **원본으로 되돌리기**: 화면의 `원본 복원`을 누르면 임시저장본을 지우고 `data/` 원본을 다시 읽습니다.

## 동작 규칙

| 항목 | 규칙 |
|---|---|
| 권한 | `PL` / `작업자` 토글로 미리보기. 작업자는 계획·PL 컬럼이 숨겨지고 실적 입력만 가능 |
| 진행상태 | 완료=작업자 실적 종료일 입력, 지연=계획 종료일이 지났는데 미완료, 진행중=실적 시작일만 입력, 미착수=그 외 |
| 정렬 | 지연 → 진행중 → 미착수 → 완료 |
| 증적 (필수) | 작업자가 실적 시작일을 입력했는데 증적이 없으면 저장 차단. 테스트는 결과가 FAIL인데 증적이 없으면 저장 차단 |
| 비고 (선택) | 저장을 막지 않음. 삭제는 본인이 등록한 항목만 |
| 검증 (V) | 설계: 물리ID 미매핑 / 개발: 설계ID 미연결 / 테스트: 개발ID 미연결 / 공통: ID 중복 |
| ID 채번 (N) | `+ 행 추가` 시 `접두어-연도-순번` 자동 부여 (ANL, SCR, DEV, TU, TI) |
| 매핑 (M) | 요구사항ID·물리ID·설계ID·개발ID는 검색 팝업에서 선택 (직접 타이핑 없음) |

## 알려진 한계 (의도적으로 제외)

- 파일을 서버에 직접 쓰지 않습니다. 저장 반영은 내보내기 후 수동 교체로 합니다.
- 엑셀 붙여넣기, 페이지네이션, 파일 실제 업로드는 없습니다 (파일명만 기록).
- 결함관리, 커버리지, 연계 캔버스, 요구사항·일정·RMS 화면은 범위 밖입니다.
- 폰트(Pretendard)는 CDN에서 받으며, 연결이 안 되면 시스템 글꼴로 표시됩니다.
