# 성과 제출용 HTML 슬라이드 작성 가이드

> 용도: 제공된 템플릿(`보고발표 템플릿 01`, 한화시스템 PPT, 29장)을 기준으로 **HTML 슬라이드를 만들고 → PDF로 저장해 한 장씩 넘겨 보는** 발표 자료를 만들 때 따르는 규칙.
> 이 문서는 "HTML을 만들 때 그대로 따라 쓰는 설계도"다. 값(좌표·색·글꼴)은 템플릿 원본에서 추출한 것이다.
> 내용 출처: `docs/제안서_추진현황_요약.md` (새 사실을 만들어 넣지 않는다 → 5장 참조)

## 0. 만들 파일

| # | 파일명(안) | 내용 | 분량(안) |
|---|-----------|------|---------|
| 1 | `deliverables/성과제출_TraceOps_ReqSync.html` | TraceOps + ReqSync 통합 성과 제출 | 14~16장 |
| 2 | `deliverables/성과제출_ProWin.html` | ProWin 성과 제출 | 9~11장 |

- 단일 HTML 파일 하나에 슬라이드 전체를 `<section class="slide">` 로 나열한다. CSS는 `<style>` 인라인.
- 이미지는 `docs/ppt-template/assets/` 의 파일을 상대경로로 참조하거나 base64로 내장(PDF 변환 시 경로 문제를 피하려면 내장 권장).

## 1. 페이지 규격 (가장 중요)

템플릿 슬라이드 크기 = **11.69 × 8.27 in = A4 가로(297 × 210 mm)**.
따라서 CSS는 **inch 단위 절대좌표**를 그대로 쓴다(템플릿 수치를 변환 없이 사용 가능).

```css
@page { size: 297mm 210mm; margin: 0; }
html, body { margin: 0; background: #888; }
.slide {
  position: relative;
  width: 11.69in; height: 8.27in;   /* 템플릿과 동일 */
  overflow: hidden;
  background: #fff;
  page-break-after: always; break-after: page;
  margin: 0 auto 0.3in;             /* 화면 미리보기용 간격 */
  font-family: 'NanumBarunGothic','나눔바른고딕','Nanum Barun Gothic','Noto Sans KR',sans-serif;
  color: #404040;
}
@media print {
  html, body { background: none; }
  .slide { margin: 0; }
  * { -webkit-print-color-adjust: exact; print-color-adjust: exact; }  /* 배경색 인쇄 */
}
```

- 슬라이드 안의 모든 요소는 `position:absolute; left/top/width/height` 를 **in 단위**로 지정한다.
- 슬라이드 1장이 PDF 1페이지가 되도록 `page-break-after` 필수. 슬라이드 밖으로 넘치면 잘리므로 **절대 `overflow` 를 풀지 않는다**(글이 많으면 줄이거나 장을 나눈다).
- 글꼴: `나눔바른고딕`(본문 Regular/Bold), `나눔바른고딕 Light`(font-weight:300, 부제·보조문구). PC에 미설치 시 PDF 변환 환경에도 설치하거나 웹폰트(`Nanum Gothic` 등)로 대체하고 줄바꿈이 깨지지 않는지 확인.

## 2. 디자인 토큰 (템플릿 추출값)

```css
:root{
  --orange-title:#EC7000;  /* 표지·마지막 장 바탕 */
  --orange-1:#F46A25;      /* 강조 도형/막대 (진주황) */
  --orange-2:#F8931F;      /* 번호 01, 막대 (밝은 주황) */
  --orange-3:#FE8D36;
  --orange-4:#EA5519;      /* 가장 진한 주황 */
  --brown:#6E5744;         /* 진갈색 막대 */
  --tan:#AF947E;           /* 연갈색 막대 */
  --sand:#D9CFC5;          /* 표 머리/보조 면 (연베이지) */
  --gray-bg:#EAEAEA;       /* CONTENTS·구분 슬라이드 바탕 */
  --gray-line:#C8C8C8;     /* 박스 테두리, 푸터 선 */
  --text:#404040;          /* 본문 */
  --text-sub:#7F7F7F;      /* 푸터·보조 */
  --white:#FFFFFF;
}
```

규칙
- **주황 계열 + 갈색 계열만** 사용. 파랑·초록 등 템플릿에 없는 색은 쓰지 않는다(차트도 주황·갈색·탄·회색 4색).
- 강조 우선순위: `--orange-1`(핵심) > `--orange-2` > `--brown` > `--tan`.
- 막대/머리 위의 글자는 흰색(주황·갈색 위) 또는 `--text`(탄·베이지 위).
- 글자 크기(템플릿 기준, pt): 표지 부제 24 / 표지 제목 48 Bold / 목차 제목 40 Bold / 본문 머리글자(소제목) 20 Bold / **본문 14** / 페이지 제목 26 Bold / 페이지 번호 "01" 36 Bold / 그림 속 라벨 12.
  → 본문은 **14pt 미만으로 줄이지 않는다.** 표 안 글자만 최소 11pt 허용.

모든 본문 슬라이드는 아래 5요소를 **동일 위치**에 둔다. 한 번 만든 뒤 복사해서 쓴다.

|------|------------------------------|--------|

| 문서 라벨 | 1.53 / 0.40 / 2.7 / 0.17 | 9pt, `--text`. 예: `성과 제출 ( TraceOps · ReqSync )` (템플릿의 "보고발표 템플릿 ( 사업명 )" 자리) |

로고 규칙(템플릿 CI 가이드): 가독성을 위해 **배경색에 맞는 로고** 사용, 크기 조정 시 **비율 유지**, 로고 변형·재채색 금지.

## 4. 슬라이드 유형 카탈로그 (템플릿 → HTML 레시피)

슬라이드마다 **아래 유형 중 하나**를 골라 쓴다. 새 레이아웃을 즉흥으로 만들지 않는다.

### T1. 표지 (템플릿 1~2장)
- 바탕: 상단 0 ~ 5.0in 영역에 `assets/bg-title-art.jpg`(주황 바탕+우상단 링 아트가 이미 들어 있는 전체 이미지)를 `background:url() top left / 11.69in auto no-repeat` 로 깔고 5.0in 에서 잘라낸다(`height:5in; overflow:hidden`). 그 아래는 흰색, 하단 7.74in 에 주황 가는 선, 푸터는 본문과 동일(저작권·로고).
- 좌상단 흰 탭: `assets/logo-title-tab.png` 를 left 1.0 / top 0, 폭 1.4in.
- 텍스트: 영문 부제 24pt Light 흰색 (left 0.78 / top 2.60) → **제목 48pt Bold 흰색** (left 0.78 / top 3.08, 폭 8.03, 최대 2줄) → 하단 흰 영역에 `발표자/부서` 14pt Bold (left 1.08 / top 5.26), 날짜 14pt Light (top 5.55, 형식 `2026.00.00`).
- 제목 후보: "TraceOps · ReqSync 성과 제출" / "ProWin 성과 제출"

### T2. 목차 CONTENTS (3~4장)
- 바탕: `assets/bg-contents-art.jpg`(회색 바탕+우상단 연한 링 아트 포함)를 슬라이드 전체에 `background-size:100% 100%` 로 깐다.
- `CONTENTS` 40pt Bold (left 1.12 / top 1.62).
- 파트별 항목: 주황(`--orange-2`) 가로 띠(두께 0.14) 위/옆에 `Part. N` 15pt Bold, 그 아래 소항목 `01 내용`, `02 내용` (14pt). 파트 3개 → 세로 간격 0.55in.
- 파트가 5개 이하면 구분 슬라이드(T3) 스타일의 `01~05` 숫자 목록(숫자 20pt Bold 주황 + 항목 20pt Light Bold, left 6.03 / top 2.82)으로 대체 가능.

### T3. 파트 구분 (4장)
- 바탕 `--gray-bg`, 좌측에 주황 가로 막대(0 ~ 4.74in, 높이 0.42, top 2.02)에 `Part. N` 20pt Bold 흰색.
- 우측 목록(left 6.03): 번호 20pt Bold `--orange-2` + 제목 20pt Light Bold. 현재 파트 항목만 진하게, 나머지는 `--text-sub`.

### T4. 2단 / 3단 / 4블록 카드 (7~10장) — **가장 많이 쓰는 유형**
- 각 카드 = **머리 막대**(높이 0.46, 14~16pt Bold) + **본문 박스**(흰 바탕, 1px `--gray-line`, 높이 최대 5.02) .
- 머리 막대 색 순서(좌→우): `--orange-1`, `--orange-2`(또는 `--brown`), `--brown`, `--tan`. 의미가 같은 카드는 같은 색.
- 2단: 각 폭 4.98 / x 0.65, 6.06 (간격 0.43). 3단: 각 폭 3.16 / x 0.65, 4.26, 7.87 (간격 0.45). 2×2: 폭 4.98 × 높이 2.4 로 위아래 배치(top 2.01 / 4.80).
- 본문 박스 안: 14pt, 줄머리 `▪`, 줄간격 1.4, 안쪽 여백 0.18. 카드당 **5줄 이내**, 한 줄 28자 이내.
- 변형: 머리 막대를 베이지(`--sand`) 배경 + `--text` 글자로 쓰면 8장 스타일(순서도 느낌), 상단 전체 가로 주황 띠 아래에 3카드를 두면 10장 스타일.

### T5. 번호 + 요약 행 (11장, 좌측 번호 원)
- 좌측 큰 원(지름 0.6, 번호 `01`·`02`·`03`, 색 `--orange-1` → `--orange-4` → `--tan`), 우측 회색 띠(`#D0D0D0`, 높이 0.55)에 소제목 + 그 아래 14pt 2~3줄.
- 우측 절반은 인용 문구(`" … "` 이탤릭 느낌) + 큰 원형 강조(`--text` 진회색 원).
- **용도: 목표 3가지(가·나·다), 하이라이트 3건 소개.**

### T6. 프로세스/타임라인 (13~18장)
- 가로 화살표 3단계(`Step 1~3`, 색은 연회색→주황→갈색 점진): 단계 머리 화살표 높이 0.6, 아래 점선 구분선 + 14pt 항목 ≤5줄.
- 세로 타임라인: 중앙 주황 세로 화살표(폭 0.28) + 원형 마커, 좌우에 흰 박스(1px 테두리, 12~14pt 2줄) 지그재그.
- 4단계 말풍선 카드(15장): 원형 아이콘 → 카드(흰, 1px 테두리) 4개 가로 나열.
- 순환 구조(16~17장): 중앙 큰 텍스트 + 원주상 5~6개 노드. 노드가 6개를 넘지 않게.
- **용도: 추진 일정, 업무 흐름(AI 추출→PL 검토→확정), 사용 순서.**

### T7. AS-IS → TO-BE (19장)
- 좌측 큰 박스(베이지 머리 `AS-IS`), 우측 2단 박스(상단 주황 머리, 하단 흰/회색)로 `TO-BE`. 사이에 `▶` 3점.
- **용도: 추진 배경(AS-IS 문제) → 목표(TO-BE 해결).** 각 박스 3줄 이내.

### T8. 원형 3요소 (20장, 가+나+다 → 결론)
- 원 3개(지름 1.3, 외곽선 `--orange-1`/`--tan`/`--orange-4`) 사이 `＋` 아이콘, 원 안에 `01/02/03`, 아래 2줄 설명. 맨 아래 어두운 띠(`#595959`)에 결론 한 줄.

### T9. 그래프·표 (22장)
- 표: 머리 행 `--text` 진회색(`#4D4D4D`) 흰 글자, 첫 열 `--sand` 배경, 나머지 흰 배경 + 가로 선만(`--gray-line`). 세로선 없음.
- 차트는 **주황·갈색·탄·회색** 4색만(도넛: `--orange-1`, `--orange-2`, `--tan`, `--gray-line`). 수치 라벨 필수, 범례는 차트 아래.
- 새 수치를 만들지 말 것: **차트는 문서에 실제로 있는 수치(예: 47개 아이디어→6개 중분류, 14개 화면, 7종 와이어프레임)만** 사용. 없으면 차트 대신 T4/T5.

### T10. 화면(프로토타입) 캡처
- 캡처 이미지 슬롯: 카드 본문 박스 안에 `object-fit:cover` 로 채움, 테두리 1px `--gray-line`, 모서리 0, 그림자 없음.
- 캡처는 로컬 서버(`python3 -m http.server`)로 `traceops-simple/`, `prowin-simple/` 를 띄워 Playwright로 **1600×900** 에서 촬영(해상도 2배). 파일명 `assets/shot-<서비스>-<화면>.png`.
- 이미지 아래 캡션 11pt `--text-sub`: `그림. 요구사항 개정 검토 화면(클릭형 프로토타입)`.
- 설계 의도를 말하는 장은 캡처 1~2개 + 설명 3줄(좌 캡처 / 우 요약) 구성.

### T11. 마지막 장 (28~29장)
- 바탕 `assets/bg-title-art.jpg` 전체(`background-size:100% 100%`), 중앙 흰 박스(폭 4.6, 높이 1.1, 좌 4.5 / 상 3.85): `End of document`(14pt) + `감사합니다`(32pt Bold), 박스 우하단 모서리에 연주황 삼각 컷.

### 템플릿에 있으나 쓰지 않는 장
5~6장(가이드), 23~27장(아이콘 목록·CI 설명)은 **가이드용이므로 결과물에 넣지 않는다**. 아이콘이 필요하면 아이콘 슬라이드의 선 아이콘 스타일(1.5px 외곽선, 단색 `--orange-2` 또는 `--brown`)을 인라인 SVG로 단순하게 그린다.

## 5. 내용 작성 규칙

1. **출처 고정**: 내용은 `docs/제안서_추진현황_요약.md` 의 문장만 사용. 숫자·날짜·기능을 새로 만들지 않는다. 문서에 없는 정량 효과(예: "시간 30% 단축")는 쓰지 않는다. 이미지로 확인된 상반기 성과는 **"설계 완료 / 프로토타입 구현"** 수준으로 표현(운영 중처럼 쓰지 않는다).
2. **한 장 = 한 메시지**: 제목은 명사형 + 결론이 보이게. 리드 문장(14pt 2줄)에 이 장의 결론을 쓴다.
3. **문장 길이**: 한 줄 28자, 한 카드 5줄. 넘치면 장을 나눈다(축소 금지).
4. **용어**: 제품명은 `ReqSync`(ReqSink 아님), `TraceOps`, `ProWin`. 상태 표현은 "구현" 대신 가능하면 "클릭형 프로토타입으로 사전 검증"과 같이 실제 수준에 맞춘다.
5. **번호 체계**: 페이지 번호 `01`~ 은 **파트 번호**(1~3개 파트), 소항목은 가·나·다 또는 ①②③ 로 통일.
6. **담당/역할 표기 금지**: 역할 구분은 원본에 없음(요약 문서 4장 확인 필요 2번). 참여자는 표지 하단에 이름만 나열(`황금빛, 홍건의, 박혜림, 서준혁`).
7. **일정**: 요약 문서의 일정(기획 ~7.14 등)은 현재(2026-11) 기준으로 이미 지난 구간이 있으므로 **"완료/진행/예정" 상태를 확인한 뒤** 기재. 확인 전에는 타임라인 장을 만들지 않는다.

## 7. PDF 저장 절차 (HTML → PDF)

```bash
# Playwright(Chromium) 사용 — 설치된 환경에서
node -e "
const { chromium } = require('playwright');
(async () => {
  const b = await chromium.launch();
  const p = await b.newPage();
  await p.goto('file://' + process.argv[1]);
  await p.pdf({ path: process.argv[2], width: '11.69in', height: '8.27in',
                printBackground: true, preferCSSPageSize: true });
  await b.close();
})();" /절대경로/성과제출_ProWin.html /절대경로/성과제출_ProWin.pdf
```
- 브라우저 인쇄로 저장할 때: 용지 **A4 가로, 여백 없음, 배경 그래픽 켬, 배율 100%**.
- 저장 후 확인: ① 페이지 수 = 슬라이드 수 ② 마지막 장 뒤 빈 페이지 없음 ③ 글자 잘림 없음 ④ 폰트 대체 없음(`pdffonts`).
