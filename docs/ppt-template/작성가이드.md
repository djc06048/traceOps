# 성과 제출용 HTML 슬라이드 작성 가이드 (v2)

> 용도: HTML로 슬라이드를 만들고 PDF로 저장해 한 장씩 넘겨 보는 한화시스템 내부 보고 자료의 작성 기준.
> v1(템플릿 도형 이식 방식)은 폐기했다. **한화시스템 템플릿에서는 색상 팔레트와 로고만 가져오고**, 구성·도형·배치는 2026년 임원 보고 기준으로 새로 설계했다.
> 예외: **표지, 목차, 엔딩**은 템플릿 형태(주황 바탕 + 링 아트)를 유지한다.
> 내용 출처는 `docs/제안서_추진현황_요약.md` 와 실제 구현 화면이다.

---

## 1. 설계 원칙

1. **한 장 한 메시지.** 표지·목차·엔딩을 제외한 모든 장은 맨 위에 **거버닝 메시지 한 문장**만 둔다. 장 번호, 장 제목, 챕터 라벨, 소제목 띠는 쓰지 않는다. 메시지가 제목이다.
2. **증거는 실제 화면.** 설명은 그림 없이 쓰지 않는다. 기능은 캡처로, 흐름은 도형으로, 문장은 최소로 보여 준다.
3. **여백이 위계를 만든다.** 박스 테두리, 헤더 띠, 장식 도형으로 구분하지 않고 **면(옅은 배경), 간격, 글자 크기**로 구분한다. 한 장에 요소는 5~7덩어리를 넘기지 않는다.
4. **색은 한 가지만 강조.** 한 장에서 강조색(주황)은 한 종류의 의미에만 쓴다. 나머지는 회색 계열과 갈색 계열로 눌러 둔다.
5. **읽는 순서 고정.** 좌→우, 위→아래. 메시지 → 그림 → 번호별 설명 순서로 눈이 움직이게 배치한다.
6. **발표해도 되고 읽어도 되게.** 장당 글자는 공백 포함 250자 안쪽, 본문은 14pt 이상(캡션·태그 제외).
7. **약점은 싣지 않는다.** 미구현·한계 사항은 `향후 계획` 장에 고도화 과제로만 쓰고, 상세 보완 목록은 개발자용 문서(`ProWin_화면보완사항.md`)에 둔다.

## 2. 페이지 규격

A4 가로(297×210mm = 11.69×8.27in). CSS는 **inch 절대좌표**를 쓴다.

```css
@page { size: 297mm 210mm; margin: 0; }
.slide { position:relative; width:11.69in; height:8.27in; overflow:hidden; background:#fff;
         page-break-after:always; break-after:page; }
@media print { * { -webkit-print-color-adjust:exact; print-color-adjust:exact; } }
```

| 영역 | 값 (in) |
|------|--------|
| 좌우 여백 | 0.70 (콘텐츠 폭 10.29, x 0.70~10.99) |
| 거버닝 메시지 | x 0.70, y 0.62, 폭 10.29, 최대 2줄 |
| 콘텐츠 영역 | y 1.90 ~ 7.40 |
| 푸터 | y 7.78 (로고 좌, 쪽번호 우) |

요소 사이 기본 간격은 0.25in, 카드 내부 여백은 0.25~0.30in.

## 3. 색상 (템플릿에서 가져온 값만 사용)

```css
:root{
  --orange:#F46A25;   /* 강조(핵심 의미 1가지) */
  --orange-2:#F8931F; /* 보조 강조, 그라데이션 */
  --orange-4:#EA5519;
  --orange-bg:#FFF0E6;/* 강조 면 (주황 10% 톤) */
  --brown:#6E5744;    /* 진한 보조, 어두운 면 */
  --tan:#AF947E;      /* 중간 보조 */
  --sand:#F3ECE5;     /* 옅은 면 (갈색 계열) */
  --gray-bg:#F7F5F3;  /* 카드 면 */
  --line:#E5E0DB;     /* 구분선 */
  --text:#2F2F2F;     /* 본문 */
  --sub:#6B6B6B;      /* 보조 문장 */
  --white:#fff;
}
```

- 사용 비율 가이드: 흰 바탕 70%, 옅은 면 20%, 주황 5~8%, 갈색 3~5%.
- 파랑, 초록 등 팔레트 밖 색은 쓰지 않는다. 차트도 주황, 갈색, 탄, 회색 4색.
- 글자색은 본문 `--text`, 보조 `--sub`. 주황 글자는 강조 키워드에만.
- 어두운 면(`--brown`) 위에는 흰색, 주황 면 위에는 흰색, 옅은 면 위에는 `--text`.

## 4. 글자

| 용도 | 크기 | 굵기 |
|------|------|------|
| 거버닝 메시지 | 24pt | Bold, 행간 1.3 |
| 카드 제목, 큰 키워드 | 16~22pt | Bold |
| 본문 | 13.5~14pt | Regular |
| 보조 설명 | 12~13pt | Regular, `--sub` |
| 캡션, 태그 | 10~11pt | Regular/Bold |

글꼴은 `NanumBarunGothic`(나눔바른고딕), 대체 `Pretendard`, `Noto Sans KR`, `Malgun Gothic`. 한 장에서 **글자 크기는 3단계까지만** 쓴다. 숫자는 Bold로 크게 보여 준다.

y 0.62  거버닝 메시지 (24pt Bold, 최대 2줄)
y 1.90  ─────────── 콘텐츠 영역 ───────────

- 로고: `assets/logo-footer.png` 높이 0.24in. 쪽번호는 우측 10pt `--sub`.
- 저작권 문구, 챕터 라벨, 장 번호, 구분 선은 쓰지 않는다.

## 6. 표지·목차·엔딩 (템플릿 유지)

- **표지**: 상단 5.0in 주황 바탕(`assets/bg-title-art.jpg`, 폭 11.69in), 좌상단 흰 탭 로고(`logo-title-tab.png`), 영문 부제 24pt Light, 제목 40pt Bold 흰색, 하단 흰 영역에 참여자. **날짜는 넣지 않는다.**
- **목차**: 회색 바탕(`bg-contents-art.jpg` 전체), `CONTENTS` 40pt, 파트별 주황 가로 띠 + 번호 항목.
- **엔딩**: 주황 바탕 전체, 중앙 흰 박스 `End of document / 감사합니다`.

## 7. 컴포넌트

| 이름 | 규격 |
|------|------|
| **카드** | 면 `--gray-bg`, 모서리 0.14in, 테두리 없음, 내부 여백 0.28in |
| **번호 원** | 지름 0.3~0.95in, 바탕 주황(또는 갈색, 탄), 글자 흰색 Bold. 단계는 원 색을 통일 |
| **태그(알약)** | 높이 0.3~0.36in, 모서리 최대, 11~12pt Bold. 역할 태그는 의미별 색 고정(주황, 갈색, 탄) |
| **체크 목록** | 주황 작은 점(0.09in 원) + 본문. 줄 간격 0.1in |
| **결과 바** | 가로 전체, 면 `--sand` 또는 `--brown`, 모서리 0.14in, 좌측 굵은 라벨 + 우측 문장 |
| **아이콘** | 선 아이콘 2px, 주황. 인라인 SVG로 단순하게(체크리스트, 브랜치, 레이어) |

| **강조 박스** | 캡처 위 주황 실선 2px, 채움 없음, 모서리 0.04in, 좌상단 번호 원(0.22in) |
| **확대 카드** | 주황 2px 테두리, 모서리 0.1in, 약한 그림자. 강조 박스와 옅은 주황 음영(12%) + 점선으로 연결 |

## 8. 슬라이드 패턴 (이 8가지에서만 고른다)

### P1. 원칙 카드 3열 (소개, 목표 요약)
카드 3개(폭 3.25, 간격 0.27, y 1.95, 높이 3.55). 카드 안: 선 아이콘(0.7) → 제목 20pt Bold → 설명 2~3줄 13.5pt. 하단 y 5.8에 갈색 결과 바(높이 1.1)로 운영 원칙 한 줄.

### P2. 문제 4열 + 시사점 바 (추진 배경)
카드 4개(폭 2.41, 간격 0.22, y 1.95, 높이 3.4). 카드 안: 큰 연번 `01`(30pt 연한 주황) → 제목 16pt Bold → 근거 2줄. 하단 y 5.65에 갈색 시사점 바(높이 1.35), 3열로 `제목 + 한 줄 설명`.

### P3. 번호 행 3줄 (목표)
행 3개(높이 1.6, 간격 0.1, y 1.95). 좌측 번호 원(0.95) → 제목 22pt Bold + 설명 14pt → 우측 주황 테두리 알약에 결과 문구. 행 사이는 `--line` 가는 선.

### P4. 전후 비교 (기대효과)
열 구성: 항목명(1.35) | 도입 전 패널(3.9, `--gray-bg`, 글자 `--sub`) | 주황 삼각 화살표(0.45) | 도입 후 패널(4.39, `--orange-bg`, 왼쪽 주황 3px 선, 글자 `--text`). 행 높이 1.08, 간격 0.14. 열 머리는 `도입 전`(회색) `도입 후`(주황) 작은 글자.

### P5. 역할별 프로세스 (업무 흐름)
4열(폭 2.31, 간격 0.35). 위에서 아래로: 번호 원 + 단계명(18pt Bold), 원들 사이 화살 선 → 역할 태그 → 카드(할 일 3줄) → 관련 화면 작은 글자. 하단에 기대 효과 결과 바. 역할 색: PM·사업관리 = 주황, 작업자 = 갈색, 제안 참여 인원 전원 = 탄.

### P6. 화면 쇼케이스 (주요 기능 상세) ★ 핵심 패턴
좌측 6.3in: **확대 카드**(위) + **전체 캡처**(아래), 확대 카드와 강조 박스를 음영 깔때기로 연결. 우측 3.54in(x 7.45): 작은 라벨 `화면 설명`(11pt 주황 Bold) + 번호 원과 설명 2~3개(제목 15pt Bold, 설명 13pt).
- 확대 카드는 이미지를 따로 자르지 않고 같은 PNG를 CSS `background-position` 으로 잘라 쓴다(강조 영역은 원본 px 좌표 4개).
- 확대 카드 높이 최대 2.3in, 폭 최대 6.3in. 전체 캡처는 남는 높이에 비율 유지. 캡션은 하단 10pt.
- 번호는 캡처의 강조 박스 번호와 우측 설명 번호가 1:1로 대응.

### P7. 타일 갤러리 (부가 기능)
4×2 또는 3×2 타일. 이미지(모서리 0.08, 테두리 `--line`) + 아래에 이름 13pt Bold + 한 줄 설명 11.5pt `--sub`. 타일 간격 0.25~0.3. 이미지 영역은 캡처의 콘텐츠 영역(사이드 메뉴 제외)을 잘라 쓴다.

### P8. 구조도 + 기술 칩 (기술 구성)
가로 3블록: `브라우저` → `서버`(안에 모듈 칩) → `저장소`. 화살표는 가는 선 + 라벨. 아래 y 5.4에 기술 스택 칩 한 줄(범주 라벨은 갈색, 값은 흰 바탕 테두리). 하단에 특징 한 줄 바.

### P9. 로드맵 (향후 계획)
좌: 고도화 과제 목록(주황 점 + 문장 5줄). 우: 하반기 계획 세로 3단계(번호 원 + 세로 연결선 + 제목 + 2줄 설명). 하단에 추진 방향 결과 바.

## 9. 거버닝 메시지 작성 규칙

- **결론을 먼저, 한 문장, 공백 포함 45자 안팎(최대 2줄).**
- 명사형·개조식으로 끝낸다. `~한다`, `~이다`, 물음표, 느낌표, 대시(—, -), 화살표(→), 슬래시 나열, 괄호 남발을 쓰지 않는다.
- 수식어 대신 **누가, 무엇을, 어떻게 바뀌는지**를 쓴다.
- 장에서 보여 주는 내용을 **요약이 아니라 의미**로 쓴다.

| 나쁜 예 | 좋은 예 |
|--------|--------|
| RFP·요구사항 관리 — 모든 제안 작업의 출발점 | RFP와 요구사항을 한곳에서 정리해 제안 작업의 기준 확립 |
| 제안서 검토 화면입니다 | 슬라이드를 보며 참여 인원 전원이 의견을 남기고 결정 근거를 기록 |
| 표준화, 자산화로 경쟁력을 강화한다 | 제안 수행이 개인 의존에서 표준 절차와 축적 자산 기반으로 전환 |

## 10. 콘텐츠 규칙

1. 사실은 `제안서_추진현황_요약.md`와 실제 화면에서만 가져온다. 새 수치, 새 효과를 만들지 않는다(정량 효과 문구 금지).
2. 상반기 성과는 `설계 완료`, `프로토타입 구현`, `사전 검증`, 구현된 기능은 `구현` 수준으로 정확히 표현한다.
3. 아직 동작하지 않는 기능(요구사항 자동 추출, 유사 사례 추천)이 흐름에 들어가면 작은 `고도화` 태그를 단다. 상세 한계는 싣지 않는다.
4. 고객사 로고 박스, 날짜, 역할 구분(담당자명)은 넣지 않는다. 참여자는 표지에 이름만.

## 11. PDF 저장

```bash
node -e "
const { chromium } = require('playwright');
(async () => {
  const b = await chromium.launch(); const p = await b.newPage();
  await p.goto('file://' + process.argv[1]);
  await p.pdf({ path: process.argv[2], preferCSSPageSize: true, printBackground: true });
  await b.close();
})();" /절대경로/성과제출_ProWin.html /절대경로/성과제출_ProWin.pdf
```
저장 후 확인: 페이지 수 = 슬라이드 수, 글꼴 대체 여부(`pdffonts`), 글자 잘림, 마지막 장 뒤 빈 페이지.

## 12. 점검표

- [ ] 거버닝 메시지만 있고 장 번호·제목·소제목이 없다
- [ ] 메시지가 45자 안팎, 대시·화살표·물음표 없음
- [ ] 패턴 P1~P9 중 하나만 사용
- [ ] 한 장 5~7덩어리, 본문 13.5pt 이상, 글자 크기 3단계 이내
- [ ] 강조색 한 가지 의미만, 팔레트 밖 색 없음
- [ ] 실제 화면 캡처에 번호가 있고 우측 설명과 1:1 대응
- [ ] 문서에 없는 수치·효과 없음, 약점 문구 없음
- [ ] 날짜·고객사 로고 박스 없음
