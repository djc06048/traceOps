01
ProWin이란?
제안(Proposal)을 통해 수주(Win)를 이끌어내는 제안관리 시스템 — 제안을 “사람 수”가 아닌 축적된 자산과 표준 절차로 수행한다
표준 절차
  • 제안 전 과정을 표준 절차·템플릿으로 체계화
  • 임시 TF·개인 역량 의존에서 탈피
  • 목차가 진척 관리의 기준(마스터)
버전관리
  • PPT 업로드 = 커밋(이력 보존)
  • 전체 섹션 최신본을 자동 합본
  • 합본은 불변 스냅샷으로 보관
자산 라이브러리
  • 과거 제안 산출물을 페이지 단위로 적재
  • 검색·재활용으로 반복 재작성 제거
  • 축적된 자산으로 제안 수행
문서 작성은 기존 오피스(PPT·엑셀)를 그대로 활용하고,
시스템은 업로드 · 처리 · 다운로드를 담당한다

01
추진 배경 (현황)
현행 제안 업무는 전담 조직·표준·시스템 없이 수작업과 개인 역량에 의존하고 있다
가. 전담 조직 부재
  • RFP마다 임시 TF를 구성
  • 매 건 처음부터 반복, 담당자 역량에 따라 품질이 좌우됨
나. 수작업 산출물
  • 조견표·합본·목차를 수작업으로 작성
  • 휴먼 에러, 버전 꼬임, 마감 리스크 발생
다. 자산의 분산·사장
  • 과거 제안 자산이 개인 단위로 분산
  • 재활용이 불가해 매 제안마다 재작성 부담
라. 구두 중심 의사결정
  • 리뷰·의사결정이 구두로 진행
  • 결정 근거가 남지 않아 추적·이관 곤란
→ 제안이 늘어날수록 품질·생산성 저하가 불가피한 구조

03
보완 필요사항 및 하반기 계획
핵심 4개 기능은 백엔드까지 구현·검증했고, 남은 화면의 DB 연결과 운영 요건을 보완한다
보완 필요사항
  • 나머지 14개 화면의 DB 연결 (현재 JSON 기반)
  • 실제 인증·권한 체계 적용 (현재 데모 계정 기반)
  • 한글 파일명 업로드의 서버 환경(UTF-8) 의존 해소
  • 합본 파일명·버전 표기 개선
  • 동시 편집 충돌 방지 (JSON 기반 화면)
  • 자산 라이브러리 적재·유사 사례 추천(Step 2) 구현
하반기 계획
  • 상세 설계 — 화면별 상세 규격 및 잔여 설계 과제 확정
  • 구현 방안 검증(PoC) — 핵심 기술 요소 실현성 검증 (PPT 업로드·합본은 구현·동작 확인)
  • 정량 성과 측정 — 개선 전·후 효율, 적용 결과 (구현 방안 확정 후 착수)
