# traceOpsReqSync

TraceOps와 ReqSync를 하나로 묶은 성과 제출 자료 폴더입니다. 구조는 `../prowin/` 과 같습니다.
**ReqSync는 TraceOps 안의 요구사항 개정 검토 모듈**입니다(같은 서버·DB, 요구사항 관리 화면의 `ReqSync` 버튼으로 진입).

```
traceOpsReqSync/
├─ README.md                  이 문서 (작성 방침, 장 구성안)
├─ capture_traceops.py        실명 마스킹 후 화면 촬영 (원본 traceops-simple 은 수정하지 않음)
├─ capture.js                 Playwright 촬영 스크립트
├─ shots/                     마스킹된 화면 캡처 12장 (1440×900 @2x)
├─ build_traceopsreqsync.py   장 구성과 문구 (작성 예정)
└─ 성과제출_TraceOps_ReqSync.html  결과물 (작성 예정)
```

공통 디자인 기준은 `../작성가이드.md`, 공통 부품은 `../tools/deck_lib.py`, 내용 출처는 `../제안서_추진현황_요약.md` 의 1장(ReqSync)과 3장(TraceOps)입니다.

## 작성 방침 (확정)

| 항목 | 결정 |
|------|------|
| 연계관리 | **포함**. ProWin 증적에 있던 연계관리(연계 캔버스) 자료를 TraceOps 장에 포함 |
| 일정 | 연말 평가 자료이므로 **일정 표현은 쓰지 않음** (요약 문서 3-5 제외) |
| 실명 | **마스킹 후 사용**. `capture_traceops.py` 가 원본을 복사해 이름을 가명(PL, 작업자A, 고객담당A, 담당자A, 수행담당)으로 치환한 뒤 촬영. 이름 목록은 저장하지 않으며, 화면에 원본 이름이 남으면 촬영을 중단 |
| 회의록 결정사항 추출 | 현재 구현은 **사전에 분석된 결과를 API로 조회**하는 방식. 장표에는 **로컬 LLM 활용**으로 기재하고, **구현 방안은 TraceOps 담당 개발자가 작성해야 하므로 "보완 필요"로 장표에 명시** |
| 호출구조 정적분석 POC | **구현되어 있고 그 결과로 연계 데이터를 추출함**(데이터: 트랜잭션 3건, 호출 노드 11개, 매핑 3건). 장표에는 성과로 기재하고, **TraceOps 안에 통합하는 작업은 보완 필요**로 기재(소스 코드는 현재 저장소에 없음) |
| 와이어프레임, PRD 정리 과정 | 와이어프레임 없이 바로 개발했으므로 **장표에서 제외** (요약 문서 3-3의 "통합 PRD v1.0", "와이어프레임 7종" 문구 사용 안 함) |
| 개발자 전달 문서 | ProWin과 같은 방식으로 `ProWin_화면보완사항.md` 형태의 문서를 별도로 작성 (로컬 LLM 추출 방안, 호출구조 POC 통합 포함) |

## 촬영 방법

저장소 루트에서 실행합니다. Python과 Node(Playwright)가 필요합니다.

```bash
python3 성과제출/traceOpsReqSync/capture_traceops.py
```

- 원본 `traceops-simple/` 과 시드 데이터는 수정하지 않고, 임시 복사본에서 마스킹한 뒤 임시 DB로 서버를 띄웁니다.
- 마스킹된 이름이 화면 텍스트에 남아 있으면 오류로 중단합니다.
- 연계 캔버스 캡처의 클래스·메서드명(예: `FcdLtrUtgu#...`)은 시스템 식별자이므로 마스킹 대상이 아닙니다. 공개 범위가 걱정되면 알려 주세요.
