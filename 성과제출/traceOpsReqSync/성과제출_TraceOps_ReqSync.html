AI 활용 성과
AI 기반 요구사항 개정 검토(ReqSync)를 포함한 TraceOps로 요구사항부터 연계까지 추적 체계를 구현했습니다.
AI 추출은 설계와 검토 화면으로 검증했으며, 로컬 LLM 연동과 호출구조 분석 통합은 보완할 예정입니다.

요구사항 상세화, 프로세스 연계, 단계 간 정합성이 회의록과 엑셀·PMS 중심의 수작업에 의존하고 있습니다.
ReqSync와 연계관리로 상세화와 연계 누락을 해결하고, 정합성이 보장되는 체계를 만들고자 했습니다.
01
ReqSync
요구사항 상세화와 증적

RFP 요구사항은 상세화되어 있지 않아 기술협상과 분석 단계에서 고객사와 협의하며 보완

보완 근거가 회의록에만 남고 반영은 수작업

02
연계관리
프로세스 단위 연계 누락

한 프로세스에 여러 메서드가 있고 담당 개발자가 서로 다름

메서드 하나가 개발 대상에서 빠지면 프로세스 전체가 동작하지 않음

03
정합성
수작업 관리와 매핑 누락

요구사항, 분석, 설계, 개발, 테스트를 엑셀과 PMS로 수작업 관리해 정합성 보장이 어려움

개발 목록을 실수로 삭제하면 요구사항이 어디에도 매핑되지 않아 누락될 수 있음

해결 방향
회의 기반 요구사항 확정ReqSync로 보완하고 증적 이력으로 보존
프로세스 단위 완결 확인연계관리로 메서드를 빠짐없이 개발 대상에 포함
정합성과 제출 활용요구사항~테스트 정합성 보장, 단계말 검토와 제출 산출물 활용

AI
AI 활용 구조AI 활용
KPI 핵심
AI는 추출과 제안을 맡고 확정은 사람(PL)이 합니다.
회의 결정사항을 요구사항에 반영하는 과정에 로컬 LLM을 활용하는 구조입니다.
회의록텍스트(.txt)로 업로드회의록 단위로 분석 결과 관리
AI결정사항 추출로컬 LLM 활용1차 생성 후 2차 검증
AI매칭 · 개정안신뢰도 표시원문 발췌와 diff 제시
PL 검토 · 확정원문과 비교문구 직접 편집, 확정 권한
반영과 이력요구사항 내역 반영근거 회의를 이력에 기록
AI가 하는 일
  • 회의록에서 결정사항과 미정사항을 추출
  • 기존 요구사항과 매칭하고 신뢰도를 표시
  • 개정안을 기존 문구와 비교해 제시
사람(PL)이 하는 일
  • 발언 원문 근거를 보고 판단
  • 개정 문구를 직접 편집
  • 반영 확정과 이력 기록은 PL이 수행
현재 상태와 보완
  • 설계 완료, 병렬 검토 화면 구현
  • AI 추출 결과(사전 분석)를 API로 조회
  • 로컬 LLM 실행 연동 보완 필요
  • 구현 방안은 TraceOps 담당 개발자가 작성
운영 원칙AI는 추출과 제안까지 맡고, 최종 확정 권한은 PL에게 두어 AI 오판 위험을 통제합니다

연계 관점
프로세스 안의 메서드 하나만 빠져도 프로세스는 동작하지 않기 때문에, 프로세스 단위로 누락을 확인해야 합니다.
통합테스트도 연계 프로세스 전체가 동작하는지로 판단합니다.
하나의 프로세스 (예: 인수지침검사)
메서드 1담당 A분석·설계·개발 완료
메서드 2담당 B분석·설계·개발 완료
메서드 3담당 C개발 대상에서 누락
메서드 4담당 D분석·설계·개발 완료
프로세스 동작 불가한 메서드만 빠져도 전체가 멈춤
PL(메인 설계자)이 프로세스를 설계하고, 하위 메서드는 개발 항목이 되어 개발자별로 배분됩니다
필요한 이유 1

프로세스는 여러 메서드의 연결

담당 개발자가 서로 달라 전체 누락 여부를 한 사람이 파악하기 어려움

필요한 이유 2

한 곳의 누락이 전체 장애

분석, 설계, 개발 대상에서 메서드 하나가 빠지면 프로세스가 동작하지 않음

필요한 이유 3

통합테스트는 프로세스 단위

연계 관점에서는 프로세스 전체가 끝까지 동작해야 정상으로 판단

TraceOps 대응
프로세스를 호출 관계(클래스·메서드)에 맞춰 캔버스로 설계하고, 각 메서드를 개발 항목과 연결해 개발 대상에서 빠지지 않도록 관리합니다.
캔버스에서 메서드별 개발 완료 여부를 확인합니다. 프로세스 단위 통합테스트 연결은 보완 필요
